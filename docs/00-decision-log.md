# Decision Log

> Architecture Decision Records (ADRs) for the IBM Cloud Architecture Diagram tool.
> Every decision below was deliberately locked during product definition. Each entry states
> the decision, the rationale, and the consequences we accept.

Status legend: **Locked** = agreed and load-bearing; changing it invalidates downstream docs.

---

## Foundation

### D1 — Custom editor engine (from scratch) · Locked
We build our own canvas/editor engine rather than embedding Excalidraw or tldraw.

- **Why:** IBM diagrams are precise, orthogonal, and spec-governed. Excalidraw's hand-drawn
  aesthetic actively fights the IBM Design Language, and neither Excalidraw nor tldraw lets us
  own the element semantics (deployedOn/deployedTo), connector nomenclature, and conformance
  linting the way an official IBM tool requires.
- **Consequence:** We rebuild canvas, selection, undo, export, and the library system. We
  mitigate the cost with a deliberately small, well-typed core (see [D2](#d2--framework-agnostic-typescript-core--thin-shells--locked)).

### D2 — Framework-agnostic TypeScript core + thin shells · Locked
The editor is a pure-TypeScript core package with **zero UI-framework dependency**. Shells
(web, VS Code, desktop) mount the core.

- **Why:** One code path for scene model, rendering, commands, undo, export, and linting means
  the same engine runs identically in a React web app, a VS Code webview, and a Tauri window.
- **Consequence:** The core exposes an imperative API and event stream; shells never reach into
  core internals. See [Architecture](02-architecture.md).

### D3 — SVG DOM rendering · Locked
The canvas renders elements as live SVG nodes, not Canvas 2D or WebGL.

- **Why:** Crisp at any zoom, native + faithful SVG export (IBM's canonical format), DOM
  hit-testing, and accessibility come almost for free. Architecture diagrams are hundreds of
  elements, not hundreds of thousands.
- **Consequence:** Very large diagrams may need viewport virtualization later; acceptable.

### D4 — Local-first, single-user, files · Locked
Diagrams are `.icad` files on disk. No backend, no accounts, no server in v1.

- **Why:** Privacy, git-friendliness, and zero infrastructure. Sharing = send the file or an
  exported SVG.
- **Consequence:** No real-time collaboration in v1 (revisit in [Roadmap](09-roadmap.md)).

### D5 — Crisp / professional visual style · Locked
Faithful to IBM Design Language: exact IBM icons (20×20 glyph in 48×48 container, 1px outline),
straight orthogonal connectors, clean typography.

- **Why:** These diagrams are stakeholder deliverables, not whiteboard doodles.
- **Consequence:** No "sloppiness" mode. Ideation happens within a clean canvas.

## Format & Interop

### D6 — `.icad` is a single human-readable JSON file · Locked
Icons are referenced by **catalog ID**, not embedded, so files stay tiny and diff cleanly.

- **Why:** Git-friendly, reviewable in PRs, trivially generated by agents.
- **Consequence:** Opening a file requires the bundled catalog version it references; we pin and
  migrate catalog versions. See [File Format](03-file-format.md).

### D7 — Export-only interop (SVG/PNG); no `.drawio` import · Locked
We export IBM-spec SVG and PNG. We do **not** import or round-trip `.drawio`.

- **Why:** A full draw.io mapping surface is large and fragile. Export covers stakeholder handoff.
- **Consequence:** No automated migration of existing draw.io diagrams in v1.

### D8 — Re-editable SVG via embedded `.icad` copy · Locked
Exported SVG embeds a copy of the `.icad` JSON in metadata so our tool can reopen and edit it —
our adaptation of IBM's "include a copy of my diagram" guidance.

- **Why:** Preserves editability across the SVG handoff without draw.io.
- **Consequence:** Exported SVGs are slightly larger; opt-out available for public assets.

### D9 — File System Access API + fallback · Locked
The web shell uses the File System Access API for real Open/Save/Save-As on Chromium; falls back
to download/upload on Safari/Firefox.

- **Why:** True "files-first" UX matching [D4](#d4--local-first-single-user-files--locked)/[D6](#d6--icad-is-a-single-human-readable-json-file--locked).
- **Consequence:** Two persistence paths to test.

### D10 — Autosave draft + crash recovery · Locked
Working state is continuously persisted (OPFS/IndexedDB); an explicit **Save** writes the `.icad`.

- **Why:** No lost work, but a clear save moment (unlike autosave-in-place).
- **Consequence:** Recovery UX on reload after a crash.

## Editor Building Blocks

### D11 — Build-time icon conversion, bundled offline catalog · Locked
A build script converts IBM SVG stencils into a versioned native catalog (optimized SVG +
metadata) shipped inside the app.

- **Why:** Full offline coverage, pinned to a known IBM icon version.
- **Consequence:** Periodic re-sync when IBM ships new icons. See [Icon Catalog](04-icon-catalog.md).

### D12 — Advisory linter + quick-fixes + optional export gate · Locked
A validation panel flags off-spec constructs (wrong container border, missing labels,
non-standard connector, reversed flow) with quick-fixes; export can optionally warn/block.

- **Why:** Guides toward compliance without blocking ideation.
- **Consequence:** We maintain a rule set. See [Spec Conformance](05-ibm-spec-conformance.md).

### D13 — Smart orthogonal connectors with IBM types · Locked
Connectors snap to shape ports, auto-route orthogonally around obstacles, carry IBM connector
semantics, and support manual override.

- **Why:** Professional density and correct IBM nomenclature.
- **Consequence:** Routing engine complexity; manual waypoints as escape hatch.

### D14 — IBM-level templates + frames · Locked
Starter templates for IBM diagram levels (system context / high-level / detailed) plus blank;
frames section, present, and jump-to via find.

- **Why:** Teaches the IBM method; organizes large diagrams.
- **Consequence:** Templates must track IBM guidance.

## Product

### D15 — MCP full authoring toolset · Locked (v2)
The MCP server exposes fine-grained tools: search catalog, add/position/style nodes+groups+zones,
connect with IBM connectors, validate, save `.icad`, export SVG/PNG, open in editor.

- **Why:** Agents build diagrams end-to-end; humans refine. Matches the A2A "GenerateArchitecture­Diagram" flow.
- **Consequence:** The core API must be complete and headless enough to drive without a UI.

### D16 — Authoring + spec + export Agent Skills · Locked (v2)
A skill set teaches agents to translate requirements → elements, apply IBM conventions, drive the
MCP, validate, and export.

- **Why:** Autonomous, spec-compliant generation.
- **Consequence:** Skills version alongside the MCP toolset. See [Agent Integration](08-agent-integration.md).

### D17 — Official / IBM-internal tool · Locked
Positioned as an official IBM tool: IBM branding, internal distribution, IBM Design sign-off.

- **Why:** Product intent.
- **Consequence:** IBM Design review gates releases; use of IBM icons/brand is sanctioned; no
  "unaffiliated" disclaimer needed.

### D18 — Carbon Design System + IBM Plex for app chrome · Locked
App shell (menus, panels, toolbars, dialogs) is built with Carbon and IBM Plex. The canvas remains
our custom SVG engine.

- **Why:** Consistency with IBM products; accessible components and themes out of the box.
- **Consequence:** Carbon is a dependency of the shells, not the core.

### D19 — Full IBM Equal Access / WCAG 2.1 AA · Locked
Keyboard-operable canvas, screen-reader annotations for shapes/connections, contrast + focus
management throughout.

- **Why:** Expected of an official IBM deliverable.
- **Consequence:** Canvas a11y is real, budgeted work. See [Accessibility](07-accessibility.md).

### D20 — MVP = editor-first web shell · Locked
v1 ships the portable core + SVG editor + IBM catalog + smart connectors + advisory linter +
`.icad` save/load + SVG/PNG export in the web shell. MCP, VS Code/desktop shells, and rich agent
skills land in v2.

- **Why:** Ships the usable core soonest; de-risks the engine before adding surfaces.
- **Consequence:** The agent headline is designed-for but not shipped in v1. See [Roadmap](09-roadmap.md).
